# Deploying Your Tax Solution Books

## Recommended host: Render

The app is one Docker container plus Postgres plus a daily scheduled job.
**Render** covers all of that in one place, which keeps the security story
simple for Plaid's questionnaire and your WISP:

- **Managed Postgres** with automated daily backups (and point-in-time
  recovery on higher plans), encryption at rest, and private networking to
  the app.
- **Automatic HTTPS** for your custom domain (certificates issued and renewed
  for you), so cookies are `Secure` and HSTS works.
- **Cron jobs** as a first-class service — the daily bank-sync backstop is a
  three-line entry in `render.yaml`.
- **Deploys the existing `Dockerfile`** as-is; secrets live in the dashboard's
  environment variables, never in the repository.
- Publishes a SOC 2 Type II report you can reference in Plaid's questionnaire
  (request it from Render and note the date in SECURITY.md).

Reasonable alternatives with the same pieces: DigitalOcean App Platform + Managed
Postgres, or Railway. The steps below are for Render; the environment
variables, migration and cron call are the same anywhere.

## Step by step

### 0. Before you start (things only you can do)

- [ ] Buy a domain (e.g. `books.yourtaxsolution.com` on a domain you own).
- [ ] Choose an SMTP provider (e.g. Postmark, Amazon SES, Microsoft 365, Google
      Workspace SMTP relay) and get host, port, username, password and a
      verified "from" address.
- [ ] Plaid: sandbox keys now; **production keys only after Plaid approves
      production access** (security questionnaire + pricing).
- [ ] Anthropic API key (console.anthropic.com) for AI categorization
      (optional; without it rules still run and the rest waits for review).
- [ ] Generate the encryption key on your own computer and **save it in your
      password manager** — a database backup cannot be read without it:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

### 1. Create the services

1. Push this repository to GitHub (it already is).
2. In Render: **New → Blueprint**, pick the repository. Render reads
   `render.yaml` and proposes: a web service (`yts-books`), a cron job
   (`yts-books-daily-sync`) and a Postgres database (`yts-books-db`).
3. For the database, choose a **paid plan that includes backups** (the free
   plan has no backups and expires). Choose the same region for everything.
4. Fill in the variables marked "sync: false" when prompted:

| Variable | Value |
| --- | --- |
| `ENCRYPTION_KEY` | the key you generated in step 0 |
| `APP_URL` | `https://books.yourdomain.com` (no trailing slash) |
| `PLAID_CLIENT_ID`, `PLAID_SECRET` | from the Plaid dashboard (sandbox first) |
| `PLAID_ENV` | `sandbox` — change to `production` only after Plaid approves |
| `PLAID_WEBHOOK_URL` | `https://books.yourdomain.com/api/plaid/webhook` |
| `ANTHROPIC_API_KEY` | optional |
| `SMTP_HOST`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | from your email provider |
| `APP_URL` on the **cron job** too | same as above |

`CRON_SECRET` is generated by Render on the web service and copied to the cron
job automatically. `DATABASE_URL` is wired from the database.

**Never set `LOCAL_DEMO` or `SEED_DEMO_DATA` on Render.** With them unset the
server refuses to start if any required secret is missing, and loads no demo
data.

### 2. Migrations

The container runs `prisma migrate deploy` every time it starts
(`scripts/docker-start.sh`), before serving. Migrations are forward-only and
safe to re-run. To run them by hand from your computer against the Render
database, use the database's *external* connection string:

```bash
DATABASE_URL="<external connection string>" npx prisma migrate deploy
```

### 3. Custom domain + HTTPS

Web service → **Settings → Custom Domains** → add `books.yourdomain.com`,
create the DNS record Render shows at your domain registrar, wait for the
certificate to be issued. Then confirm `APP_URL` and `PLAID_WEBHOOK_URL` use
that domain.

### 4. First login

There is no demo data in production, so create your own account once, from your computer:

```bash
DATABASE_URL="<external connection string>" ENCRYPTION_KEY="<your key>" npx tsx scripts/create-owner.ts "you@yourtaxsolution.com" "Your Name" "Your Office LLC"
```

It prints a one-time password. Sign in, set up two-step verification, then
change nothing else until you've confirmed the backup (step 7).

### 5. Plaid webhook

The webhook URL is sent to Plaid with every Link session, from
`PLAID_WEBHOOK_URL`. In the Plaid dashboard you can also set it under
**Developers → Webhooks**. Test in sandbox: connect a bank with
`user_good` / `pass_good`, then check the business's audit log for
`bank_connection.webhook` entries.

### 6. Daily sync

`render.yaml` schedules `node scripts/cron-sync.mjs` daily at 10:17 UTC. It
calls `POST /api/cron/sync` with the `CRON_SECRET`. Check it from the cron
job's **Logs** tab (a line like `[cron-sync] 200 {"success":true,…}`). Run it
on demand with **Trigger Run**. Any other scheduler can do the same call:

```bash
curl -fsS -X POST -H "Authorization: Bearer $CRON_SECRET" https://books.yourdomain.com/api/cron/sync
```

### 7. Backups and restore (do a test restore before go-live)

- Render backs up the database daily on paid plans (and offers point-in-time
  recovery on higher plans). Confirm in **Database → Recovery/Backups**.
- **Test restore (record date and result in SECURITY.md § 9):**
  1. In the database's backup page, restore a backup **to a new database**
     (never over the live one).
  2. Point a copy of the app (or your laptop) at the restored database with
     the same `ENCRYPTION_KEY`:

     ```bash
     DATABASE_URL="<restored db external URL>" ENCRYPTION_KEY="<your key>" npm run dev
     ```
  3. Sign in, open a client's Months page and a P&L, and confirm the numbers
     match production. Then delete the restored database.
- Also keep an occasional off-platform copy (encrypted) with `pg_dump`:

```bash
pg_dump "<external connection string>" --format=custom --file=books-$(date +%F).dump
```

  Restore it with `pg_restore --clean --no-owner --dbname "<target URL>" books-YYYY-MM-DD.dump`.

## Production checklist

- [ ] `PLAID_ENV=production` **only after** Plaid approved production access,
      with production `PLAID_CLIENT_ID` / `PLAID_SECRET`.
- [ ] `LOCAL_DEMO` and `SEED_DEMO_DATA` are **not** set; no demo data in the database.
- [ ] `ENCRYPTION_KEY` is your own random key, saved in your password manager.
- [ ] Custom domain on HTTPS; `APP_URL` and `PLAID_WEBHOOK_URL` use it.
- [ ] Test invitation email received (SMTP works) — Team page → Invite a client.
- [ ] Daily sync cron run shows `200` in its logs.
- [ ] **Backups verified with a test restore**, recorded in SECURITY.md.
- [ ] Privacy policy, terms, and the client consent wording reviewed by your
      attorney and the placeholder pages replaced.
- [ ] SECURITY.md brackets filled in; app added to the office's WISP.
- [ ] Every staff member has two-step verification set up (Team page shows it).
